# Feature Comparison: SwiftUI OpenCoder vs React Native OpenCode Mobile

This document provides a detailed comparison of features between the current SwiftUI iOS app (OpenCoder) and the older React Native version (opencode-ios), based on code analysis of key components like chat features, tool integrations, session management, and UI elements. The analysis identifies differences, shared capabilities, and missing features in the Swift app for achieving feature parity, with a focus on enhancing the chat interface, tool visualization, and development workflow integration.

## Overview

- **SwiftUI App (OpenCoder)**: Native iOS app with TCA-based architecture. Emphasizes SSH server management, remote task execution via tools, Live Activities for progress tracking, and a chat interface using ExyteChat for message rendering. Core logic in OpenCoderCore (platform-agnostic), UI in OpenCoderUI (iOS-specific). Supports enhanced message parts (reasoning, tools), session management, provider/model selection, and basic attachments.
  
- **React Native App (opencode-ios)**: Cross-platform (iOS/Android/Web) Expo app. Focuses on AI chat with Claude, real-time tool execution visualization, session management, and GitHub integration. Uses Expo Router for navigation, Context for state, and specialized components for tools, attachments, and commands. Rich chat UI with FlashList for messages, advanced input handling, and built-in commands.

Both apps integrate with OpenCode API for chat, tools, and sessions, but differ in platform depth, UI richness, and specific integrations.

## Missing Features in Swift App (Detailed Recommendations for Parity)

Based on code review, the Swift app has a solid foundation for chat and tools but lacks some RN's polish in UI interactions and integrations. Prioritize:

1. **Advanced Tool Visualizations (High)**: 
   - Implement views for RN's unique tools: Grep (search results with highlights), Glob/List (file lists), WebFetch (URL previews), Task (sub-task trees).
   - Add line counts, file paths, and state badges to all Swift tool views (like RN's ToolStateIndicator).
   - Use expandable sections for all outputs, with auto-expand for short content.

2. **GitHub Integration (High)**:
   - Port GitHubPicker: Modal with tabs (issues/PRs), search scoped to current repo (detect via git tool), preview with comments/reviews.
   - Convert GitHub items to message parts/attachments for chat context.
   - Add GitStatus view, refreshing on session idle via events.

3. **Rich Input & Commands (High)**:
   - Enhance input with ImageAwareTextInput-like features: Detect image pasting, file suggestions, command autocomplete.
   - Add CommandSuggestions dropdown for /commands, handling built-ins (/init, /share, /summarize) async.
   - Support command args and menu (e.g., via long-press or button).

4. **Media & Attachments (High)**:
   - Expand beyond images/videos: Full file picker/previews, decode content for display (like RN's FilePart).
   - Add full-screen viewers and attach menu with GitHub option.

5. **UI Polish (Medium)**:
   - Persistent error banners/toasts (ChatErrorBanner).
   - Model selection dialogs, quota display for providers like Chutes.
   - Swipe navigation, haptics for interactions.

6. **Session Enhancements (Medium)**:
   - Dedicated Sessions tab with list, create/share/unshare.
   - Session URL display and copy.

These would align Swift's chat richness with RN while leveraging native iOS features.

## Unique Strengths

- **SwiftUI**: Native performance, deeper iOS integration (Live Activities, SwiftUI previews, TCA testing), modular packages for macOS reuse. Strong tool views with clean output parsing.
- **React Native**: Cross-platform, mature chat ecosystem (FlashList for perf, Reanimated), advanced integrations (GitHub, commands). Easier web parity and rapid prototyping.
